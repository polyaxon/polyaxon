# Track your first experiment

This quick start assumes that Polyaxon and its execution agent are already running.

Run a training simulation on your machine and send its parameters, metrics, and visualizations to Polyaxon. By the end, you will have two runs that differ by one hyperparameter and are ready to compare.

This part does not schedule compute or use Kubernetes, a container, or the Polyaxon Agent.

## Before you start

You need Python and access to a Polyaxon gateway, either [Polyaxon Cloud](https://cloud.polyaxon.com) or a Community Edition deployment.

Install the Polyaxon CLI, Python library, and simulator dependencies:

```bash
python3 -m pip install --upgrade polyaxon numpy matplotlib
```

## Connect the CLI to your Polyaxon gateway

The CLI and tracking library send requests through a Polyaxon gateway. Connect to the gateway that hosts your project.

For Polyaxon Cloud, configure the gateway and log in:

```bash
polyaxon config set --host=YOUR_GATEWAY_URL
polyaxon login
```

The login command opens your token page and asks you to paste the token into the terminal.

For Community Edition with the default `ClusterIP` service, connect with:

```bash
polyaxon port-forward
```

This command exposes the gateway and configures the CLI. If your gateway is already exposed, configure its URL with `polyaxon config set --host=<YOUR_GATEWAY_URL>`. Community Edition does not require `polyaxon login`.

## Create a project [#create-a-project]

A project groups related runs and their tracked data. Create one for this guide:

```bash
polyaxon project create \
  --name=quick-start \
  --description="Runs from the Polyaxon quick start" \
  --tags=quick-start
```

Creating `quick-start` also caches it as the current CLI project, so the CLI commands below work without `-p quick-start`. The guide includes it to make the target project explicit.
To set it as the local project for the current directory instead, run `polyaxon init -p quick-start`; you can then omit `-p quick-start` from Polyaxon CLI commands. Keep `--project=quick-start` when running the simulator because that is an argument to the example script.

If you cannot create projects in your organization, use an existing project and replace `quick-start` below with its full `OWNER/PROJECT` name.

## Run the simulator

Download the example:

```bash
curl -fLO https://raw.githubusercontent.com/polyaxon/polyaxon-quick-start/master/tracking/simulate_dl_experiment.py
```

Run a baseline experiment:

```bash
python3 simulate_dl_experiment.py \
  --project=quick-start \
  --run-name=baseline \
  --epochs=20 \
  --seed=42 \
  --batch-size=64 \
  --learning-rate=0.001
```

The script simulates 20 training epochs with a fixed seed. It does not train a model or need a GPU, but its loss and accuracy respond to the supplied hyperparameters. It logs:

- Hyperparameters as run inputs.
- Training, validation, and per-class metrics at each epoch.
- Weight and gradient histograms at regular checkpoints.
- Confusion matrices and ROC and precision-recall curves.
- Weight distributions, gradient flow, feature activations, and loss-landscape images.
- Progress, text snapshots, and final and best results.

The core tracking calls are the same ones you can add to a real training script:

```python
from polyaxon import tracking

project = "quick-start"
run_name = "baseline"

tracking.init(project=project, name=run_name)
tracking.log_inputs(learning_rate=0.001, epochs=20)

for epoch in range(1, 21):
    tracking.log_metrics(step=epoch, train_loss=0.5, validation_accuracy=0.8)

tracking.log_outputs(best_validation_accuracy=0.8)
tracking.end()
```

When the run finishes, the script prints its Polyaxon run ID.

## Inspect the run

Open the project dashboard:

```bash
polyaxon project dashboard --project=quick-start --yes
```

Open the run named `baseline`. Its inputs and outputs describe the experiment, while its metrics and visualizations show how training changed across epochs.

## Compare two runs

Run the same simulation with a higher learning rate:

```bash
python3 simulate_dl_experiment.py \
  --project=quick-start \
  --run-name=faster-learning-rate \
  --epochs=20 \
  --seed=42 \
  --batch-size=64 \
  --learning-rate=0.003
```

Both runs use seed `42` and the same remaining inputs. The second run converges faster and finishes with higher validation accuracy, so the effect of the learning-rate change is visible rather than buried in random variation.

Return to the project's runs table, select `baseline` and `faster-learning-rate`, then open the comparison view. See [Compare runs](/docs/tracking/runs-dashboard/comparison) for the available tables and charts.

## What you verified

The simulator created two user-managed runs and sent their metadata and events to Polyaxon. The experiment code stayed on your machine; Polyaxon did not schedule or execute it.

This verifies your client configuration, project access, tracking calls, dashboards, and run comparison. It does not yet verify an Agent, queue, or managed workload.
