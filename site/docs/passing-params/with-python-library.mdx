Sometimes you may need to handle or request the resolved inputs and outputs directly from the API or using the Python library.

## Overview

Polyaxon provides a [Python Library](/docs/references/python-library/polyaxon-client/) that exposes several methods to fetch information about a run or the currently running operation.

Users can use the library to request the full resolved params (inputs and outputs) and use it during the runtime of their programs. They can additionally add, update,
or reset the inputs or outputs programmatically.

## Example with the `RunClient`

Let's look at a simple program that just prints some information based on an input using the basic [Runclient](/docs/references/python-library/run-client/):

```python
from polyaxon.client import RunClient

client = RunClient()
print(client.get_inputs())
```

In order to run this program, we can use the following Polyaxonfile [`passing-params/python-run-client.yaml`](https://github.com/polyaxon/polyaxon-quick-start/blob/master/passing-params/python-run-client.yaml):

```yaml
version: 1.1
kind: component
name: python-run-client-parameters
inputs:
  - name: message
    type: str
run:
  kind: job
  init:
    - file:
        content: |
          from polyaxon.client import RunClient

          client = RunClient()
          print(client.get_inputs())

        filename: main.py
  container:
    image: polyaxon/polyaxon-quick-start
    workingDir: "{{ globals.run_artifacts_path }}/uploads"
    command: [python3, main.py]
```

Now you can run multiple version of this example:

```bash
polyaxon run -f passing-params/python-run-client.yaml -P message="test 1" -l
```

```bash
polyaxon run -f passing-params/python-run-client.yaml -P message="test 2" -l
```

## Example with the tracking module

In the previous example we used the `RunClient` which is a high-level Python library to interact with the Run API.
`RunClient.get_inputs()` refreshes the run data when the inputs have not been loaded.

In most situations, and especially for operations running in-cluster, users will need to interact with their runs using the [run tracking class](/docs/references/python-library/tracking/client/) or the [tracking module](/docs/references/python-library/tracking/module/),
which provides several more methods for logging and versioning results.

The module also performs several more initializations steps, including an implicit refresh, to provide the latest version of the metadata before your program starts.

Let's rewrite the program:

```python
from polyaxon import tracking

tracking.init()
print(tracking.TRACKING_RUN.get_inputs())
```

The Polyaxonfile is available as [`passing-params/python-tracking.yaml`](https://github.com/polyaxon/polyaxon-quick-start/blob/master/passing-params/python-tracking.yaml):

```yaml
version: 1.1
kind: component
name: python-tracking-parameters
inputs:
  - name: message
    type: str
run:
  kind: job
  init:
    - file:
        content: |
          from polyaxon import tracking

          tracking.init()
          print(tracking.TRACKING_RUN.get_inputs())

        filename: main.py
  container:
    image: polyaxon/polyaxon-quick-start
    workingDir: "{{ globals.run_artifacts_path }}/uploads"
    command: [python3, main.py]
```

Now you can run multiple version of this example:

```bash
polyaxon run -f passing-params/python-tracking.yaml -P message="test 1" -l
```

```bash
polyaxon run -f passing-params/python-tracking.yaml -P message="test 2" -l
```
